# 需求规格：HangoutDuck 第一阶段（展示前）可开展工作计划

## 元信息
- 档位：标准（阈值 ≤ 0.20，上限 12 轮）
- 轮数：10
- 最终歧义度：0.19
- 是否有残余风险：有（见「残余风险」，主要是小组人数、展示具体日期、舵机确切型号、JetPack 版本未确认）
- 日期：2026-09-25

## 清晰度分布
| 维度 | 得分 | 权重 | 备注 |
|---|---|---|---|
| 意图 | 0.80 | 0.25 | 学习复刻为主，但 1–2 个月内有一次展示，需要保底演示 |
| 结果 | 0.75 | 0.22 | 先手写步态走起来（保底），再上 RL；RL 展示前只需仿真可行 |
| 范围 | 0.85 | 0.20 | 只做下半身 10 舵机，拴线，现成模块，不画 PCB |
| 约束 | 0.85 | 0.15 | 硬件基本齐全，只缺驱动板与 IMU；主板 Jetson Nano；有 CUDA 电脑 |
| 验收 | 0.80 | 0.10 | 底线：手写步态拴线平地连续走 ≥10 步不摔 |
| 背景 | 0.85 | 0.08 | 参考 LuwuDynamics/xgoduck（1910 版 Microduck）；团队人数未知 |

加权歧义度 = 1 − (0.80×0.25 + 0.75×0.22 + 0.85×0.20 + 0.85×0.15 + 0.80×0.10 + 0.85×0.08) ≈ 0.19

## 意图
小组想通过复刻 Microduck 学习整套双足机器人技术栈（机械装配、电控、底层驱动、步态、RL/sim2real）。没有课程/比赛的硬性交付，但 **1–2 个月内有一次展示**，因此需要一个"无论 RL 成不成都能动起来"的保底演示。RL 是学习主线，手写步态是展示保险。

## 期望结果
展示时（1–2 个月后）：
1. 一只只有下半身（两条腿各 5 自由度，共 10 个飞特 1910 舵机）的 HangoutDuck，由桌面上的 Jetson Nano 经 USB 拴线控制；
2. 用**手写保底步态**在平地上连续向前走 ≥10 步不摔；
3. 在 MuJoCo 仿真中展示下半身版本的 **RL 行走策略**（真机 RL 是加分项，不是底线）；
4. 仓库中沉淀可复用的：关节表、接线图、舵机驱动层、Nano 上的 50 Hz 运行时、仿真模型、步态代码，为后续 RL 上真机、上身无线化打基础。

## 范围内

### 总体路线
- 机械：沿用已打印好的 xgoduck 结构件（仅腿部与躯干），关节布局/顺序沿用 Microduck/xgoduck。
- 电子：**全部现成模块 + 杜邦/舵机线**；USB 总线舵机驱动板 + USB 输出的 IMU，均接到 Jetson Nano。舵机与 IMU 以外的供电走桌面电源。
- 软件：在 Nano 上自写轻量 Python 运行时（50 Hz 控制循环），保底步态与 RL 策略共用同一套运行时与关节约定。
- 仿真/RL：fork `xgoduck_rl`（已含 1910 的 BAM 执行器模型），改成下半身 10 自由度版本后重新训练。

### 关键路径
```
今天下单驱动板/IMU ──▶ 设 ID + 零位 ──▶ 整机装配与关节表 ──▶ Nano 运行时站立 ──▶ 吊架上步态 ──▶ 平地步态（展示底线）
                         ▲                                    ▲                     ▲
   不等硬件即可并行：  舵机驱动代码、Nano 环境          仿真下半身模型 ──────────▶ 在仿真里先调步态参数
                                                          └──▶ RL 训练（并行主线，不挡关键路径）
```

### 推荐选型（执行方可直接拍板的范围内给出的默认值）
- **驱动板**：USB 转半双工 TTL 的飞特总线舵机驱动板，二选一：微雪 Bus Servo Adapter (A)（LeRobot SO-100 社区常用）或飞特官方 FE-URT-1。两条腿各走一路总线，供电线粗而短。到货后先用 1 个舵机验证 1910 能 ping 通、能同步读写。
- **IMU**：选 **USB 输出、自带姿态解算**的 6/9 轴 IMU（例如维特智能 WT901 系列 USB 版），输出频率 ≥100 Hz。理由：Nano 离板拴线，I²C 走长线不可靠，USB IMU 不需要额外单片机。
- **软件**：Python 3 + numpy，第一阶段**不用 ROS**；策略推理用 onnxruntime，装不上时退回 numpy 手写 MLP（策略只是小 MLP）。若 JetPack 自带 Python 太旧，用 miniforge 装独立环境。
- **仓库结构（建议）**：
  ```
  hardware/   BOM、接线图、joints.yaml（关节表，全仓库唯一真源）
  tools/      ID 设置、零位标定、单关节扫动、总线频率测试
  runtime/    舵机总线、IMU、控制循环、安全模块
  gait/       保底步态
  sim/        下半身 MJCF、步态仿真脚本
  rl/         xgoduck_rl 的 fork（子模块或独立仓库）
  docs/       本文档、周报、测试记录
  ```

## 范围外 / 非目标
- **头颈部全部不做**：只买了 10 个舵机，颈/头/嘴（xgoduck ID 30–34）本阶段不装、不控、不进仿真动作空间。
- **不自己画 PCB**：不复刻 xgoduck 扩展板，全用现成模块。
- **不做无线化**：Jetson Nano 不上身、不配机载电池，全程桌面电源 + 拴线。
- **不做头部交互**：无摄像头、激光/ToF、语音、表情等。
- **不移植官方运行时**：不移植 Microduck 的 Rust 运行时，也不移植 xgoduck 的 Uno Q 运行时（它绑定 Arduino Bridge/Zephyr，无法直接迁到 Nano）。
- **RL 真机部署不是展示前的必须项**：展示底线只要求 RL 在仿真中能走。

## 决策边界
执行方（Claude 或组员）**可直接决定、不必回来确认**：
- 驱动板与 IMU 的具体型号（在常见现成模块内，单件几十到一两百元量级）
- 软件技术选型：语言、是否用 ROS、仓库目录结构、代码规范、推理方式
- 仿真模型改法：删头颈的方式（直接删除/等效配重）、质量参数修正、奖励与训练超参
- 保底步态的实现方式：关键帧/IK/正弦轨迹、是否加 IMU 反馈、参数整定方法

**必须回小组确认**的事项：
- 超出上述小额模块的采购（如加买舵机、换主板、买电池）
- 改变机械结构或重新设计/重印结构件
- 改变展示目标或及格线
- 任何需要改动已明确的非目标的事（如临时决定做头部、做无线化）

## 约束
- 时间：**1–2 个月内有一次展示**，关键路径按 4 周排。
- 硬件：打印件、轴承等已齐；**10 个飞特 1910 已到货**；**缺驱动板和 IMU**；Jetson Nano 在手；有 CUDA 显卡电脑。
- 主板：Jetson Nano（GPU 为 Maxwell 架构，**无法跑 mjlab/MuJoCo Warp 训练**，只做推理和控制；训练在 CUDA 电脑上）。
- 拴线：Nano 离板，USB 线同时承载舵机总线与 IMU，线缆拖拽会影响行走。
- 腿部构型：每腿 hip yaw / hip roll / hip pitch / knee / ankle（只有踝俯仰、没有踝侧摆），侧向平衡主要靠髋侧摆。
- 预算：未明确，默认只做小额现成模块采购。

## 被暴露的假设及其处理
| 假设 | 暴露方式 | 处理 |
|---|---|---|
| "模仿 Microduck"就是照 Microduck 原版做 | 预检发现 Microduck 用 XL330，而 xgoduck 才是 1910 版的 Microduck | 以 xgoduck 为参考基线（第 3 轮） |
| 1910 需要自己做执行器辨识才能做 sim2real | 预检发现 `xgoduck_rl` 已含 1910 BAM 参数（`1910_m6.json`） | 直接复用，真机上再验证；是否需要重新辨识视 A9 情况再定 |
| xgoduck 的运行时可以直接用 | 查证其绑定 Arduino Uno Q（Bridge/Zephyr/STM32） | 在 Nano 上自写 Python 运行时（第 8 轮列为非目标） |
| Nano 要装到鸭子身上 | 场景压测：Nano 开发套件尺寸/重量/功耗远超 xgoduck 机身预留 | 先离板拴线，上身以后再说（第 4 轮） |
| "先手写"是为了验证硬件 | 施压回合重新追问 | 实为保底演示 → 引出展示节点（第 5、6 轮） |
| 项目"没有硬性节点" | 与"需要保底"矛盾 | 更正为 1–2 个月内有展示（第 6 轮） |
| 现成策略/观测可直接复用 | 第 8 轮得知只有 10 个舵机、只做下半身 | 动作 14→10 维、观测 61→约 39 维，需改 MJCF 并重训 |
| 运行时一定跑在 Nano 上 | 用户称主板"好像是 Jetson Nano" | 以 Nano 为目标平台；运行时写成纯 Python，CUDA 电脑可临时替代 Nano 做联调（待确认） |

## 施压回合的发现
- **第 2 轮 → 第 5 轮**：第 2 轮用户选了"先手写，后 RL"。得知 `xgoduck_rl` 已有 1910 执行器模型、手写步态对 5 自由度腿成本不低之后，第 5 轮追问手写的真实目的，答案从隐含的"验证硬件"变成了"**保底方案**"。
- **第 1 轮 → 第 6 轮**：第 1 轮用户选"学习复刻，没有硬性节点"，与"保底"矛盾。第 6 轮追问后确认 **1–2 个月内有展示**。这一改动把整份计划从"RL 主线优先"变成"保底步态是关键路径，RL 并行"。
- **第 3 轮 → 第 4 轮（场景压测）**：用户提出主板可能是 Jetson Nano。用"Nano 装进 xgoduck 机身"的场景压测后，确定先离板拴线，驱动板问题因此简化为"USB 总线舵机板"。

## 事实来源

### [已查证]
- 仓库现状：只有 `README.md`（一行标题），1 个初始提交。来源：本仓库。
- Microduck：约 25 cm、约 800 g，15 个 Dynamixel XL330（14 个受策略控制），RK3566（Radxa Zero 3W），Rust 运行时，50 Hz；训练仓库 `microduck_rl` 用 mjlab（MuJoCo Warp）+ PPO，需 CUDA GPU，导出 ONNX，执行器模型用 BAM（只有 XL330）。来源：[pollen-robotics/microduck](https://github.com/pollen-robotics/microduck)、[pollen-robotics/microduck_rl](https://github.com/pollen-robotics/microduck_rl)、[pablo-mano/microduck-replica](https://github.com/pablo-mano/microduck-replica)
- Microduck 腿部构型：每腿 hip yaw/roll/pitch、knee、ankle（5 自由度），颈/头 4 自由度 + 嘴。来源：[microduck-replica](https://github.com/pablo-mano/microduck-replica)
- xgoduck：沿用 Microduck 外形、15 舵机关节布局与顺序，换成 15 个飞特 1910 + Arduino Uno Q + 自制扩展板（QMI8658 IMU、舵机接口、电源、串口缓冲）；提供 STL、Altium PCB、BOM、装配手册；README 未写许可证。来源：[LuwuDynamics/xgoduck_hardware](https://github.com/LuwuDynamics/xgoduck_hardware)
- `xgoduck_rl`：`microduck_rl` 的下游 fork，1910 的 BAM 参数在 `1910_m6.json`，需 CUDA GPU、Python 3.12、uv，Apache-2.0；README 未报告真机结果。来源：[LuwuDynamics/xgoduck_rl](https://github.com/LuwuDynamics/xgoduck_rl)
- `xgoduck_runtime_arduino`：Linux 端 50 Hz ONNX 推理，MCU（STM32U585/Zephyr）100 Hz 舵机总线（1 Mbps）+ IMU；ID 10–14、20–24 为腿，30–33 为颈/头，34 为嘴；观测 61 维 = 陀螺 3 + 重力 3 + 关节位置 14 + 关节速度 14 + 上一动作 14 + 速度指令 3 + 头部 4 + 6 个零；强依赖 Uno Q。来源：[LuwuDynamics/xgoduck_runtime_arduino](https://github.com/LuwuDynamics/xgoduck_runtime_arduino)
- 飞特 HD-1910-C001：空心杯、TTL 串行总线、10 kg·cm、5–8.4 V，34×20 mm。来源：[OpenELAB 产品页](https://openelab.io/products/feetech-hd1910-microduck-coreless-servo)（搜索摘要）
- 飞特 SCS/STS 系列默认波特率 1 Mbps。来源：[feetech-cli](https://github.com/iory/feetech-cli)、[Feetech 入门教程](https://www.feetechrc.com/Data/feetechrc/upload/file/20201127/start%20%20tutorial201015.pdf)

## 残余风险
- **小组人数与分工未知**：计划按工作包写，没有按人头排期。建议 3 条并行线：① 硬件/电控（WP0、WP5、WP6）② 底层软件/运行时（WP2、WP4、WP9）③ 仿真/步态/RL（WP3、WP7、WP8）。人少时优先保证 ①② 和 WP7。
- **展示具体日期不确定（1 还是 2 个月）**：已按 4 周排关键路径，若只有 1 个月，第 4 周没有缓冲。
- **采购周期**：驱动板/IMU 是唯一硬阻塞，晚一天到货，关键路径就晚一天。
- **去掉头颈后质心变化**：xgoduck 的步态/策略参数是按带头整机设计的，仿真里必须用实称重量修正，否则仿真里调好的步态上真机会失效。
- **没有踝侧摆**：侧向平衡只能靠髋侧摆，保底步态侧向稳定性可能是最难调的部分。
- **拴线拖拽**：线缆重量和张力会干扰行走，需要吊挂或让人托线。
- **USB 串口延迟**：USB 转串口可能带来毫秒级延迟和抖动，需在 A2/A5 实测。
- **许可证**：xgoduck_hardware 未声明许可证，Microduck 3D 模型为 CC BY-SA-NC；学习用途没问题，公开发布前需核对。
